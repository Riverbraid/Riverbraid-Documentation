# GitHub Visibility Notes for Riverbraid

This document records practical, non normative visibility improvements for Riverbraid's public GitHub surface.

It does not define protocol authority, verification rules, governance claims, or technical correctness.

## Purpose

Riverbraid's public surface should help builders quickly understand:

- What Riverbraid is
- Where to start
- What can be verified
- What is not being claimed
- Which repositories matter first

## Highest leverage public surfaces

1. Riverbraid organization profile
2. Riverbraid-Evaluation-Kit
3. Riverbraid-Core
4. Riverbraid-Golds
5. Riverbraid-Documentation
6. Primary Gold surfaces such as Safety, Refusal, Judicial, and Crypto

## Recommended organization profile

Open source deterministic integrity floor for AI governance, making structure, authority, and drift visible before trust is granted.

## Recommended pinned repositories

- Riverbraid-Evaluation-Kit
- Riverbraid-Core
- Riverbraid-Golds
- Riverbraid-Documentation
- Riverbraid-Safety-Gold
- Riverbraid-Refusal-Gold

## Repository metadata

Use short, role specific About descriptions rather than one identical description everywhere.

Universal topics:

- riverbraid
- ai-governance
- ai-safety
- deterministic-ai
- fail-closed
- verification

Role specific topics may include:

- cryptography
- refusal

- governance
- hash-witness
- protocol
- reproducibility

## README surface standard

Each important public README should make clear:

1. What this repository is
2. How it relates to Riverbraid
3. Where verification starts
4. What evidence is available
5. What is not being claimed

## Community health files

The .github repository should eventually provide:

- CONTRIBUTING.md
- SECURITY.md
- CODE_OF_CONDUCT.md

These files should not contain fake contact addresses or imply more support capacity than currently exists.

## Non claims

These visibility improvements do not claim:

- More technical maturity
- More adoption
- More verification
- More safety
- More production readiness
- More external validation

They only improve public readability and discoverability.

## Current priority

3. Top repo About descriptions
4. Top repo topics
