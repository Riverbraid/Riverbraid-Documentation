# Integration Guide

**Status**: DRAFT / NO REGISTRY MUTATIONS  
**Scope**: how external projects can integrate with or alongside Riverbraid

## What this guide covers

This guide is for teams who want to:

- run the Riverbraid Evaluation Kit as a check in their own CI
- reference Riverbraid verification output as part of their own governance evidence
- build a custom verifier following the Riverbraid pattern
- understand safe claim language when referencing Riverbraid

This guide does not cover:

- modifying Core
- adding a repository to the Evaluation Kit registry
- claiming Riverbraid certification
- claiming production readiness

## Integration Path A - Run the Evaluation Kit in your own CI

This is the simplest integration. A project may fork or reference the Evaluation Kit and run it as a step in its own pipeline.

What you get:

- evidence that the pinned Riverbraid registry state was verifiable in your environment on the date you ran it
- your own evidence record for that run

What you do not get:

- any claim about your own system's behavior
- any approval from Riverbraid
- any certification
- any inference about repositories outside the current registry

Minimum evidence to preserve:

```yaml
riverbraid_evaluation_kit_commit:
run_date:
run_environment:
result:
output_artifact:
non_claims:
```

Correct claim language after a pass:

```text
Riverbraid Evaluation Kit: PASS
Scope: pinned registry entries at configured commits
Non-claim: this does not certify our system or claim production readiness
```

Do not use certification or approval language.

## Integration Path B - Reference Riverbraid as a governance precedent

A project may cite Riverbraid as an architectural reference or pattern source.

Correct citation language:

```text
This system uses a governance pattern inspired by Riverbraid.
It does not claim to be Riverbraid or to inherit Riverbraid verification status.
Its own verification evidence is [location].
```

What to preserve:

- claimed state versus executed state
- fail-closed behavior
- documented non-claims
- independent evidence path

## Integration Path C - Build a custom verifier following the Riverbraid pattern

A Riverbraid-aligned verifier should:

1. take a defined input state
2. check a defined invariant
3. exit zero on success
4. exit nonzero on failure or ambiguity
5. produce deterministic output for the same input
6. document scope and non-scope

Minimal verifier sketch:

```js
#!/usr/bin/env node
// Scope: [what this checks]
// Non-scope: [what this does not check]
// Failure behavior: exits 1 on any boundary violation

import { existsSync, readFileSync } from 'fs';

const REQUIRED_FILE = 'BOUNDARY.json';

function fail(reason) {
  console.error(`FAIL: ${reason}`);
  process.exit(1);
}

function pass(message) {
  console.log(`PASS: ${message}`);
  process.exit(0);
}

if (!existsSync(REQUIRED_FILE)) {
  fail(`required file missing: ${REQUIRED_FILE}`);
}

let data;
try {
  data = JSON.parse(readFileSync(REQUIRED_FILE, 'utf8'));
} catch (error) {
  fail(`could not parse ${REQUIRED_FILE}: ${error.message}`);
}

if (!data.claim_level) {
  fail('missing required field: claim_level');
}

pass(`${REQUIRED_FILE} is present and valid`);
```

What makes this Riverbraid-aligned:

- it fails closed
- it has defined scope
- it is deterministic
- it documents what it does not check

What makes this not Riverbraid-canonical:

- it is not registered in the Evaluation Kit
- it has not been through registry succession
- it carries only the evidence generated by its own project

Use this label:

```text
Riverbraid-aligned verifier - not a canonical Riverbraid Gold petal
```

## Integration Path D - Create an applied governance profile

Applied profiles are future surfaces for domains such as data-center governance, education AI oversight, public-sector transparency, and research reproducibility.

Minimum scaffolding:

- `ADAPTATION.md`
- `CLAIMS.md`
- `NON_CLAIMS.md`
- `EVIDENCE.md`
- `KNOWN_LIMITATIONS.md`

Do not imply that an applied profile inherits canonical Riverbraid status.

## Compatibility language reference

| Situation | Correct label |
|---|---|
| You ran the Evaluation Kit and it passed | Riverbraid Evaluation Kit: PASS (scope: pinned registry) |
| You built a verifier following the pattern | Riverbraid-aligned verifier |
| You adapted the architecture for your domain | Riverbraid-inspired governance surface |
| You are running a pilot using Riverbraid as a base | Riverbraid-based pilot - [domain] |
| You are citing Riverbraid as a reference | Governance pattern sourced from Riverbraid |

## Getting help

Open an issue in Riverbraid-Documentation describing the integration use case.

Open an issue in Core or Evaluation Kit only when a specific defect is observed in those repositories.

## Non-claim

This guide does not create certification, approval, production readiness, external audit, or canonical status for any integration.
