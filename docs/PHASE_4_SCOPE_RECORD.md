## Purpose

This document records the intended boundary for Phase 4 maturity scaffolding without unlocking implementation.

Phase 4 exists to make Riverbraid easier to audit, easier to verify, easier to explain, easier to navigate, and easier to consume as a stable deterministic governance substrate.

The goal is not to make Riverbraid look finished.

The goal is to make Riverbraid easier to understand without making it easier to misunderstand.

## Governing rule

Trust above reach.
Accuracy above impressiveness.
Boundaries above persuasion.
Evidence above momentum.

Riverbraid is useful only to the degree that its claims remain smaller than or equal to its evidence.

## Documentation clarity rule

Documentation clarity is not scope expansion.

Documentation clarity is claim hygiene.

Documentation refinement does not add scope when it clarifies existing claims, lowers ambiguity, improves first reader navigation, labels maturity more clearly, separates verified from unverified surfaces, names evidence requirements, reduces friction without changing protocol behavior, or improves familiar open source navigation.

Structural scope changes occur when work adds code, changes verifier behavior, changes registry status, changes workflow enforcement, changes release or tag state, changes security settings, changes package behavior, creates a new executable path, mutates canonical artifacts, or claims a new verified capability.
